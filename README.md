# GDP 等价地图

> 选一个省/州或国家，看它相当于哪些国家/省/州之和。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

[▶ 在线试用](https://gdp.newzone.top/) · [本地运行](#跑起来)

```bash
npm install
npm run dev
```

![打开就有结论](docs/preview-first-screen.png)

「广东 GDP ≈ 韩国」「河南相当于 52 个国家之和」这类对比图到处都有，但都是死图。这个项目把它做成一个可以自己玩的小工具：选地区 → 自动匹配 → 出图 → 分享链接。纯静态、不需要账号，所有计算在浏览器里。

## 能做什么

打开就有结果：默认先给「广东省」，不用点任何东西就能看到一张图和一句结论。

| 模式 | 输入 | 输出 |
| --- | --- | --- |
| 地方 → 世界 | 选 1~N 个省/州（中国省级行政区、美国各州、欧洲 NUTS-1、日本都道府县） | 世界地图上高亮等价的对照对象，并给出「≈ N 个国家」 |
| 世界 → 地方 | 选 1 个国家 | 世界地图上高亮等价的省/州组合（跨国混搭，比如「日本 ≈ 得克萨斯州 + 浙江省」） |

**每个结果都会先给一句反事实结论**——这是整个工具最想让人记住的一句：

> **假如河南省是一个国家**：总 GDP 世界第 22 位，人均第 86 位，面积第 88 位，人口第 17 位

另有**拼图玩法**（点「玩一局」）：目标是把某个省/州的体量用**最多 3 个国家**拼出来，
合计不许超过目标、越接近越好；提交后给出本局 0–100 分、最优解，还可以「挑战好友」；
「看答案」不计成绩，选满 3 个会自动提交。
宽屏在地图上点国家，**手机上地图只有 180px 高、小国点不中，改用一份可点的国家清单**。
一旦超了目标就当场说（「超了 X —— 取消一个再试」），不等凑满三个。

**玩法视图**（顶栏的「玩法」tab）把对照工具变成几个随时能玩的小游戏，进度只存在浏览器里（没有账号、没有后端）：

- **每日挑战**：按日期抽「地区 + 可累加指标」，最多 3 个国家、合计不超过目标；给出 0–100 分与本地连胜，
  分享 5 格色条；「挑战好友」把同一题和你的分数发成链接，对方打开就玩同一题。
- **Higher / Lower**：两张卡猜谁更大，连对计数，最佳存本地。
- **盲猜轮廓**：给一个等积投影剪影，四选一，10 题一轮。
- **经济护照**：选过的参照物自动盖戳，按中国 / 美国 / 欧洲 / 日本 / 国家分组，进度存本地。

**六个指标**（同一个地方，可以比不同的东西）：

| 指标 | 河南省的结果 | 得克萨斯州的结果 |
| --- | --- | --- |
| 总 GDP | ≈ 52 个国家之和（超出 1.4%） | ≈ 82 个国家之和（超出 1.7%） |
| 平价 GDP | ≈ 45 个国家之和（1.86 万亿美元，平价口径） | ≈ 57 个国家之和（2.91 万亿美元，平价口径） |
| 人均 GDP | ≈ 格鲁吉亚（9,141 美元/人） | ≈ 新加坡（90,672 美元/人） |
| GDP 密度 | ≈ 特立尼达和多巴哥（497.5 万美元/km²） | ≈ 捷克（437.4 万美元/km²） |
| 面积 | ≈ 突尼斯（16.4 万 km²） | ≈ 缅甸（67.7 万 km²） |
| 人口 | ≈ 越南（1.01 亿人） | ≈ 尼泊尔（3,125 万人） |

人均 GDP 与 GDP 密度不可累加，所以只能跟**单个**对象比：选它们时只保留「最像的一个」口径，地区也只能选一个
（选新的会替换旧的，URL 里的 `st` 也会被锁成 `nearest`）；总量、平价、面积、人口可以累加，于是有**四种凑法**——
面板上每一种都直接把结果写出来，不用背术语：

| 凑法 | 河南省（8,835 亿美元）的结果 | 说明 |
| --- | --- | --- |
| 尽量多凑 | 51 个 · 8,604 亿（少 2.6%） | 从最小的国家往上加，能加多少算多少 |
| 宁可超出 | 52 个 · 8,956 亿（多 1.4%） | 装不下的那一个也算进去，保证至少这么大 |
| **比大国家** | **巴西的 41%** | 只跟体量最大的 10 个比，看它是其中哪一个的几分之几 |
| 最像的一个 | 波兰 · 9,086 亿（多 2.8%） | 不凑，只挑最接近的那一个 |

「比大国家」里的**大国 = 按当前指标排名前 10**（GDP 口径就是 GDP 前十：美、中、德、日、印、英、法、意、加、巴），
结果直接写成「河南省 ≈ 巴西的 41%」这种几分之几的说法。
这个分数**不会超过 100%**——「占日本的 115%」是句错话；要是目标比最大的那个大件还大，
就加上别的大国，写成「美国 + 中国的 63%」。

再配合「忽略微型经济体（人口不足 100 万）」开关，可以把图瓦卢、瑙鲁这类微型国家从结果里剔掉。
选**两个**地方时，结果卡会多出一块「两个目标对比」：总量、人均、面积、人口逐项摆开，并说清谁大多少
（「广东省是河南省的 2.2 倍」「广东省高出 71.3%」）。地图上两个参照物也用**两种颜色**标出来（青色、紫色），
图例直接写上两个名字，看得出谁是谁。此外还有彩蛋：参照物在世界上排第几位、
这批国家一共住着多少人、**同一比例尺的面积剪影对照**（河南 vs 突尼斯并排一比，谁大谁小一眼可见）。

**换个组合**：结果卡上可以切换「原版 / 熟脸 A/B / 随机」；熟脸版只从编辑精选的常见国家里凑 3–6 个，按体量从大到小列出，误差直接标出来。URL 带 `v`，分享链接打开还是同一版。

- **2D 世界地图**：Natural Earth 投影，中国省级与美国州界作为细分层叠在国家之上，右下角附南海诸岛小图
- **3D 地球**：正射投影球面，**倒过来看**（能看到北极斜着退到后面）、有明暗与大气辉光，拖动松手后还有惯性；
  参照地区与等价对象之间连大圆弧线（被球体背面遮住的部分会断开，不会横穿地球）
- **方形图**：世界按当前指标重画，每块的大小就是它的份额，**从地面立起方块**（高度也跟数值走）；
  高亮的是这次对照出来的对象（「世界 → 地方」模式下对照出来的是省/州、不在图上，
  这时高亮的是参照的那个国家）
- **擂台**：两个地方逐项 PK 打出比分（总 GDP / 平价 / 人均 / 密度 / 面积 / 人口），
  两边各写一次名字，比分和每一项都对得上列；右边是省/州前 16 名的对阵树（写着名字，数值跟在后面）
- **排行榜**：把对象按当前指标排成条形榜。它回答名次卡回答不了的那句「我选的这个，在同类里到底排第几」——
  不只给名次，还把前后邻居有多大摆出来。**国家和省/州排在同一张榜上**（国家侧取参照物自己那一年），
  所以「假如它是一个国家」那个名次可以直接在榜上核对；榜上可切「只看国家 / 只看省/州」。
  换指标换年份时是**排行追逐**：形态照流行的「GDP 追赶」做——数值挂在条形末端、条形自己会生长、
  名次变了的行互相让位，一眼看得见「谁超过了谁」；而且名次旁边标着「▲3 / ▼1 / 新」，
  动画让你看见动、标记告诉你动了多少。
  省/州行后面还标着「≈ 93 国」：它相当于多少个国家加起来（跟结论卡上的件数同一口径）
- **年份回溯**：**目标和对照的世界都按同一年比**——把滑块往前拨，参照物的大小也跟着变
  （「今天这个地方放在当年是什么水平」）。国家侧可回到 **1960 年**（第一年有正式统计的年份：
  世界银行 + IMF WEO）；省/州侧看它自己的数据——**美国各州 1997–2025、中国省级 2000–2024、
  欧盟一级区 2000–2024、港澳台 1960–2025**，日本府县 2023。
  年份控件**只放目标有数据的年份**：目标只有一年时控件就只剩那一年，并在旁边说清楚为什么。
  ⚠️ **1960 年以前只有麦迪逊项目的「估算」**：省/州在那些年份根本没有统计，
  拿今天的省去比当年的猜测，结论是拼出来的——所以那些年份不发布。
- **随机一题**：随机抽一个地方 + 一个指标 + 一套口径，一键换一个话题
- **今日一地**：按日期确定性地抽一个地区——今天所有人打开看到的都一样，方便互相发；
  它和「玩法 → 每日挑战」是同一道题（同地区、同指标、同年份）
- **拼图玩法**：见上
- **玩法视图**：每日挑战、Higher / Lower、盲猜轮廓、经济护照（见上）
- **搜索**：中文 / 拼音 / 拼音首字母都能搜（`广东` / `guangdong` / `gd` / `Texas`）
- **地图上的国家可以点**：点一下会切到「世界 → 地方」，看它相当于哪些省/州；
  图注里有提示，切换后会有一条 toast 说明切到了哪个国家
- **分享**（右上角「分享」）：
  - 复制链接——选择状态、指标、口径、年份都写进 URL，对方打开就是同一张图
  - 下载分享卡——竖版 2400px 宽（标题 + **结论大字** + 四项排名 + 地图 + 出处），适合发群
  - 下载高清图——横版 3600px 宽
  - 下载动图——把目标有数据的年份回溯导成 GIF（默认选中广东是 2000→2024），一帧一年；
    帧里的标题垫着半透明底板（压在亮色高亮上也看得清），底部有一条进度线
  - 玩法视图里的每日成绩 / 挑战链接——复制 5 格色条 + 得分 / 连胜，或只复制挑战链接（玩视图不提供地图导出）
- **桌面端是一整屏**：页面自己不滚（侧栏的内容比一屏长，它自己滚），
  地图按**可用高度**决定多大——窗口越宽地图越大（1920 宽的屏幕上地图长到 1394 宽），
  窗口矮的时候地图自动缩窄，不会压到页脚上
- **界面顺序**按新用户动线排：**先给结论**（结果卡在侧栏最上面），紧接着就是「选地方」，
  然后才是换换口味、指标、年份、口径。手机上顺序是「地图 → 结论 → 选地方 → 换换口味 → 指标 → 口径 → 年份」
  （窄屏把口径提到年份前面，与桌面相反），顶栏实测约 161px，结论的首行落在第一屏里；图注上的「换个地方」会把焦点直接送到搜索框。
  **主要控件一律露在外面**，不塞进折叠的「更多选项」——
  「▶ 播放」和年份滑块就在指标下面第一屏，进阶选项只剩一个「忽略微型经济体」开关
- **地图上面有一句「人话」图注**：结论那行是数字（「≈ 52 个国家之和」），
  图注是这句话的意思（「这 52 个国家加起来，也就抵得上一个河南省」）——
  不用自己翻译地图上那一片颜色是什么；换指标、换年份，图注也跟着变
- **对比是动态的**：换指标、换口径、换年份时，结论里的数字从旧值滚到新值，结果列表的条形滑到新长度，
  地图上的高亮从旧颜色淡到新颜色——「它变了」这件事本身就是要让人看出来的。
  全站只认**一条缓动曲线、三档时长**（运动 0.55s / 反馈 0.18s / 入场 0.32s；
  加载圈那种一直转的另有一档 0.8s），
  数字滚动的时长也直接从 CSS 的 `--dur` 读，不另写一份。
  **拖年份滑块时颜色立刻跟手**（过渡会暂时关掉——0.55s 的过渡追不上滑块，地图会看着发糊），
  松手才恢复过渡。
  换视图（地图 ⇄ 地球 ⇄ 方形图 ⇄ 擂台 ⇄ 排行 ⇄ 玩）也有入场过渡，不再是「啪」地一下换掉。
  系统开了「减少动态效果」就全部变成瞬间切换，但页脚的**「动效」开关**能自己决定要不要看动画
  （系统说别动时也照样能打开）；系统确实关了动画时，页面还会弹一句说明，点一下就打开动效

## 跑起来

```bash
npm install
npm run dev       # http://localhost:5173
```

> 锁文件里的依赖指向官方源 `registry.npmjs.org`（不是国内镜像）——CI 跑在 GitHub runner 上，
> 把一个第三方镜像放在构建关键路径上既慢又多一份可用性风险。
> 本地想用镜像加速，临时改 npm registry 就行，**别把镜像写进锁文件**。
> 要跟 CI 完全一致（按锁文件装），用 `npm ci`。

数据产物已经提交在 `public/`，首次运行不需要抓数据。要更新数据再跑：

```bash
npm run data
```

`npm run data` 会同时抓国家、中美两省、欧洲 NUTS-1 与日本都道府县四套源；
其中欧洲与日本那两套是 `scripts/fetch-regions.mjs` 单独负责的。

其它命令：

```bash
npm run build     # 类型检查 + 打包到 dist/
npm run test      # 核心算法、价格基准与玩法单元测试
npm run preview   # 预览打包结果
npm run acceptance # 浏览器级验收（自带服务器，不用先起 dev server）
npm run audit:ui   # 多分辨率 UI 审计：9 个分辨率 × 16 个场景，量溢出/裁切/触摸目标，还导出全站文字
npm run screenshots # 重新生成 README 里的预览图
node scripts/websearch.mjs "查询词"   # 网页搜索（DeepSeek Search & Fetch API，要 DEEPSEEK_API_KEY）
```

想对着 dev server 跑验收：`node scripts/acceptance.mjs http://localhost:5173`。
CI（`.github/workflows/ci.yml`）跑的就是 typecheck → 单测 → 构建 → 浏览器验收。

## 数据从哪来

| 侧 | 来源 | 口径 |
| --- | --- | --- |
| 国家 | IMF《世界经济展望》2025 年 4 月版（经 DBnomics 镜像） | 名义 GDP + 人口，1990–2025 逐年；现价美元 / 百万人，2025 为该版预测值 |
| 国家（1960–1989） | 世界银行 NY.GDP.MKTP.CD + SP.POP.TOTL | 名义 GDP + 人口，现价美元；与 WEO 衔接（美国 1989 → 1990 连续） |
| 国家（1700–1950） | ~~麦迪逊项目~~ | **不再使用**：那是估算而非统计，而省/州在那些年份没有统计，混在一起比的结论是拼出来的 |
| 国家面积 | mledoze/countries 的面积表（原样取用，含内陆水域） | 平方公里 |
| 中国省级 | 国家统计局《中国统计年鉴》表 3-9《地区生产总值》+ 表 2-5/2-6《分地区年末人口数》 | 名义 GDP（亿元），**2000–2024 逐年**；2000–2011 取年鉴网页版的 HTML 表（程序解析），2010–2024 取年鉴表格图片的读数（落库在 `data/provincial-gdp-history.json`）；按当年年均汇率折美元；人均 = GDP ÷ 人口 |
| 港澳台 | IMF WEO（1990 起）+ World Bank NY.GDP.MKTP.CD / SP.POP.TOTL（1960–1989） | 香港 1960–2025、澳门 1982–1989 + 2001–2025（1990–2000 无统计）、台湾 1990–2025；走省级池，不进国家池 |
| 中国省面积 | DataV.GeoAtlas 边界几何（球面面积换算） | 平方公里，估算值 |
| 平价换算 | IMF WEO 的 PPPGDP ÷ NGDPD | 中国 2.035、美国 1.000（美国是 PPP 基准，恒为 1）、香港 1.390 |
| 美国各州 | BEA 州级名义 GDP 与人口（SAGDP2 现价美元 + SAINC4 人口，1997–2025） | 美元；人均由「总量 ÷ 人口」算；面积按 us-atlas 州界几何算 |
| 欧洲 NUTS-1 | Eurostat `nama_10r_3gdp` / `nama_10r_3popgdp`（2000–2024，逐年） | 94 个一级区（德国 16、法国 14、土耳其 12…），边界 Eurostat GISCO；「整个国家算一个 NUTS-1」的（如捷克、丹麦）不重复收录 |
| 日本都道府县 | 内阁府《府县民经济计算》与总人口（2023 年度） | 47 个都道府县，边界 Natural Earth；内阁府汇总里有 5 个县（石川、奈良、德岛、香川、宫崎）显示「-」，那 5 个从各府县自己公布的结果里读 |
| 汇率 | World Bank `PA.NUS.FCRF` | 年均官方汇率 |
| 价格基准（兜底） | World Bank `NY.GDP.DEFL.ZS`（美国 GDP 平减指数） | 两边通常取同一年，系数为 1；数据源给出不同年份时用它折算（只有比率有意义：1960→2024 差 8.16 倍） |
| 世界边界 | Natural Earth（经 D3 graph gallery 转换，ISO3 编号） | 台湾并入中国轮廓 |
| 中国边界 | 阿里云 DataV.GeoAtlas | 34 个省级行政区 + 南海诸岛（符合国内地图合规要求） |
| 美国州界 | us-atlas（TopoJSON，FIPS 编号） | 州界几何 |

交叉校验：31 个省合计与全国 GDP 差 0.72%（地区加总 ≠ 全国的正常口径差）；
美国 51 个州合计与全美 GDP 差 **0.13%**。

省级数据的数值是从年鉴官方表格（图片）人工读取后落库的（`data/provincial-gdp-2024.json`
是 2024 年，`data/provincial-gdp-history.json` 是 2010–2024 年的逐年读数），
原图保留在 `data/raw/`，来源链接写在页面页脚，点击「官方原表」可核对。
2000–2011 年的部分是年鉴**网页版**的 HTML 表，程序直接解析，不经人手。

## 算法

只有一小块是自己写的，其余都是成熟库（`src/lib/match.ts`）：

- `accumulate(target, pool, { order, rule })`：一个带两种顺序（升序/降序）和两种规则
  （装得下就加 / 装不下的那一个也算进去）的通用累加器，四种对照方式都由它组合出来
- `matchByStrategy(target, pool, strategy)`：把四种口径包成统一入口
- `closestSingle`：单个最接近的对象

累加是贪心的，所以结果是「一组对象」，不是一个；件数（51 个 / 3 个）正是这个工具想给的那个数字。
指标定义在 `src/lib/metrics.ts`（数值格式化、标题模板、能不能累加），换指标不用动算法。

## 技术选型

刻意保持轻量，没有 SSR、没有状态库、没有 UI 框架：

- Vite + React 19 + TypeScript
- d3-geo（投影 / 路径）、d3-scale / d3-scale-chromatic（配色）
- 地图与地球都是**纯 SVG**：没有 WebGL，低端设备与截图导出都能跑
- 数据管线是 Node 脚本（`scripts/`），产物落在 `public/data` 与 `public/geo`
- 发布的 JSON 按真实精度收口：钱到元、人到人、人均到分、坐标到 5 位小数（约 1.1 米）——
  源数据多给的那几位精度只是白下载

### 为什么不用 three.js

3D 地球是用 d3-geo 的正射投影画的**纯 SVG**，不是 WebGL。这个选择不是情怀，是算过的账：

- **导出链路是决定性的。** 分享卡、高清图、GIF 三种导出都是「克隆当前 SVG → 画进 canvas → 栅格化」，
  所以屏幕上的图和导出的图**一定是同一张**。WebGL 画出来的东西没法序列化成 SVG，
  要接上导出就只能维护两套渲染器（屏幕一套、导出一套），而且导出的还会跟屏幕不一样；
  或者导出降级成位图，丢掉矢量质量。
- **性能不是瓶颈。** 实测 SVG 地球每帧重算 402 条路径（屏幕上常驻 261 条，欧洲与日本的 141 条只在高亮时画），
  拖动跟手。three.js 能把投影搬到 GPU 跑到 60 fps，还能加真正的着色器（大气散射、昼夜线、城市灯），
  但为此要付上面那笔账，还要多背约 150 KB 的运行时。
- **环境风险。** 之前用 globe.gl（就是 three.js）时，在受限环境里把页面渲染进程卡死；
  而且没有 GPU 的环境（headless、部分虚拟机）WebGL 会整个黑屏，SVG 不会。

真要更「真」的 3D 质感，SVG 里也做得出来：滚转角（把球倒过来看）、明暗渐变、大气光晕、星空背景、
顶面高光——地球现在这几样都有。

## 数据更新

`npm run data` 会重新抓取 IMF WEO 与汇率；年鉴换新版本时，替换 `scripts/fetch-sources.mjs` 里的年鉴图片地址，
并更新 `data/provincial-gdp-2024.json` 里的读数与年份，再跑一次 `npm run data:build` 即可。
（2000–2011 那段年鉴 HTML 表是 `scripts/build-data.mjs` 里的 `fetchYearbookTable` 直接抓的，不走 `data/raw`。）

## 已知边界

- **PPP 口径只有国家侧是官方数**：国家用 IMF 的 PPPGDP；省/州没有同口径的 PPP 源，
  用所属国家的 PPP 换算因子估算（页面上写明了）
- **熟脸组合是编辑精选，不是客观的「最出名」排名**：它只从几十个常见国家里凑 3–6 个，
  误差会直接标在结果卡上，可能比原版大；随机组合用固定种子，分享链接里的 `v` 决定是哪一版
- **省/州侧的数据年份不一样**：中国省级 2000–2024、美国各州 1997–2025、欧洲 NUTS-1 2000–2024，
  日本都道府县只有 2023 年，年份控件只放**目标有数据**的年份，
  两边都取那一年比（所以不用再跨年折价）
  （欧盟 94 个区里有 7 个有缺口：比利时三区 2003 年起、罗马尼亚四区只有 2000–2001 与 2012 年起）
- **1960 年以前不发布**：只有麦迪逊项目的估算，而省/州在那些年份没有统计，
  拿今天的省去比当年的猜测，结论是拼出来的
- 省/州现在覆盖中国、美国、欧洲 94 个 NUTS-1 一级区与日本 47 个都道府县；
  欧洲 NUTS 之下的一级（NUTS-2）、日本的市町村暂未接入（管线加一份源文件即可扩）
- 省级面积是按边界几何估算的（与官方公布值相差 1% 上下）；省级**人均**由「GDP ÷ 人口」算
  （年鉴公布的人均用的是年均人口，与我们发布的年末人口在旧年份能差 9%，三个指标必须自洽）
- 中国省级的历史值是**各版年鉴当时公布的数**：经济普查修订（三经普、五经普）会改动历史年份，
  所以相邻年份之间存在口径断点（如北京 2023→2024 涨 12%，2000→2001 涨约 50%），本项目不做跨版推算
- **玩法进度只存在本地**：每日成绩/连胜、Higher / Lower 与盲猜最佳、经济护照都在浏览器 localStorage；
  清缓存或换浏览器会丢，没有账号、没有后端、也没有全球排行榜。挑战好友是一个带目标与分数的静态链接
  （分数只作展示，按 0–100 夹取）
- 面积剪影对照用等积投影，保证画出来的大小就是真实大小之比

## 部署

纯静态站，没有后端、没有 API 调用、构建产物就是几个 JSON + 一个 JS 包：

```bash
npm run build     # 产物在 dist/
```

仓库已经接了 **GitHub Pages**（`.github/workflows/pages.yml`），推送到 `main` 自动部署；
自定义域名是 `gdp.newzone.top`（`public/CNAME`），DNS 加一条 CNAME 指向 GitHub Pages 即可。
`dist/` 也可以直接丢到任何静态托管（静态托管 / Nginx 都行）。
`vite.config.ts` 里 `base: './'` 用的是相对路径，放子目录也能跑。
数据是构建期抓取好的静态 JSON，运行时不再访问外部接口。

首屏只下载 `data/regions.json`（每对象的默认年，约 35 KB gzip），
其余年份在 `data/regions-history.json`（约 342 KB gzip）里，页面加载后才合并——
这样手机上不用为了一个结论先等 700 多 KB（那是一个文件时的体积）。**两个文件都要部署**。
