# GDP 等价地图

> 选一个省/州，看它的 GDP 相当于多少个国家之和。浏览器本地算，不用注册。

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE) [![365 开源计划 #046](https://img.shields.io/badge/365%20%E5%BC%80%E6%BA%90%E8%AE%A1%E5%88%92-%23046-1f6feb)](https://github.com/rockbenben/365opensource)

[▶ 在线试用](https://rockbenben.github.io/gdp-map/) · 189 个国家 + 226 个省/州，6 个指标，逐年可回溯 · [本地运行](#给开发者)

![打开就有结论：广东省 ≈ 72 个国家之和](docs/preview-first-screen.png)

「广东 GDP ≈ 韩国」「河南相当于 52 个国家之和」这类对比图到处都有，但都是死图——只能看，不能自己换。这个项目把它做成能自己玩的小工具：选一个省/州，它自动找出体量相当的国家，在地图上高亮出来，结论写成一句「≈ 52 个国家之和」。

和静态对比图不同的地方有三处：数字是逐年对得上的（目标与参照物取同一年，不做跨年折价）；指标能换（GDP / 人均 / 面积 / 人口）；对照方式能换（凑一组、宁可超出、跟最大的 10 个比、只挑最像的一个）。全部在浏览器里算，没有账号、没有后端。

## 支持范围

| 方面 | 支持情况 |
| --- | --- |
| 形态 | 纯静态网页，打开即用；手机上也能用（窄屏会把地图换成一份可点的国家清单） |
| 地区 | 国家 189 个；省/州 226 个——中国 34 个省级行政区、美国 51 个州、欧洲 94 个 NUTS-1 一级区、日本 47 个都道府县 |
| 指标 | 总 GDP / 平价 GDP / 人均 GDP / GDP 密度 / 面积 / 人口，共 6 个 |
| 年份 | 国家 1960–2025（2025 年是 IMF 预测值）；中国省级 2000–2024、美国各州 1997–2025、欧洲 NUTS-1 2000–2024、港澳台 1960–2025、日本都道府县 2023。年份控件只放**目标有数据**的年份 |
| 联网 | 首次打开要下载数据（首屏约 36 KB gzip，历史数据按需再拉）；之后计算全在本地，不调用任何外部接口 |
| 账号 | 不需要注册登录，没有服务端，成绩与进度只存在本机浏览器 |
| 浏览器 | 现代浏览器（Chrome / Edge / Safari / Firefox）；桌面端是一整屏，窄屏自动换布局 |

## 能做什么

### 两种对照方向

| 模式 | 输入 | 输出 |
| --- | --- | --- |
| 地方 → 世界 | 选 1~N 个省/州 | 世界地图上高亮等价的对照对象，并给出「≈ N 个国家」 |
| 世界 → 地方 | 选 1 个国家 | 高亮等价的省/州组合（跨国混搭，比如「日本 ≈ 得克萨斯州 + 浙江省」） |

每个结果先给一句反事实结论——这是整个工具最想让人记住的一句：

> **假如河南省是一个国家**：总 GDP 世界第 22 位，人均第 86 位，面积第 88 位，人口第 17 位

### 六个指标，同一个地方可以比不同的东西

| 指标 | 河南省的结果 | 得克萨斯州的结果 |
| --- | --- | --- |
| 总 GDP | ≈ 52 个国家之和（超出 1.4%） | ≈ 82 个国家之和（超出 1.7%） |
| 平价 GDP | ≈ 45 个国家之和（1.86 万亿美元，平价口径） | ≈ 57 个国家之和（2.91 万亿美元，平价口径） |
| 人均 GDP | ≈ 格鲁吉亚（9,141 美元/人） | ≈ 新加坡（90,672 美元/人） |
| GDP 密度 | ≈ 特立尼达和多巴哥（497.5 万美元/km²） | ≈ 捷克（437.4 万美元/km²） |
| 面积 | ≈ 突尼斯（16.4 万 km²） | ≈ 缅甸（67.7 万 km²） |
| 人口 | ≈ 越南（1.01 亿人） | ≈ 尼泊尔（3,125 万人） |

人均 GDP 与 GDP 密度不可累加，只能跟**单个**对象比：选它们时只保留「最像的一个」口径，地区也只能选一个（URL 里的口径参数会被锁成 `nearest`）。

### 四种凑法，面板上每一种都直接把结果写出来

| 凑法 | 河南省（8,835 亿美元）的结果 | 说明 |
| --- | --- | --- |
| 尽量多凑 | 51 个 · 8,604 亿（少 2.6%） | 从最小的国家往上加，能加多少算多少 |
| 宁可超出 | 52 个 · 8,956 亿（多 1.4%） | 装不下的那一个也算进去，保证至少这么大 |
| **比大国家** | **巴西的 41%** | 只跟体量最大的 10 个比，看它是其中哪一个的几分之几 |
| 最像的一个 | 波兰 · 9,086 亿（多 2.8%） | 不凑，只挑最接近的那一个 |

「比大国家」里的**大国 = 按当前指标排名前 10**（GDP 口径就是 GDP 前十：美、中、德、日、印、英、法、意、加、巴），结果写成「河南省 ≈ 巴西的 41%」这种几分之几的说法。不会出现「占日本的 115%」这种错话——目标比最大的大件还大时，写成「美国 + 中国的 63%」。

再配合「忽略微型经济体（人口不足 100 万）」开关，可以把图瓦卢、瑙鲁这类微型国家从结果里剔掉。选**两个**地方时，结果卡会多出一块「两个目标对比」：总量、人均、面积、人口逐项摆开，并说清谁大多少；地图上两个参照物用**两种颜色**标出来，图例直接写上两个名字。

### 六种看法

- **2D 世界地图**：Natural Earth 投影，中国省级与美国州界作为细分层叠在国家之上，右下角附南海诸岛小图
- **3D 地球**：正射投影球面，**倒过来看**、有明暗与大气辉光，参照地区与等价对象之间连大圆弧线（被球体背面遮住的部分会断开，不会横穿地球）
- **方形图**：世界按当前指标重画，每块的大小就是它的份额，**从地面立起方块**（高度也跟数值走）
- **擂台**：两个地方逐项 PK 打出比分，两边各写一次名字，右边是省/州前 16 名的对阵树
- **排行榜**：对象按当前指标排成条形榜，国家与省/州同榜；换指标换年份时是**排行追逐**——名次变了的行互相让位，名次旁边标着「▲3 / ▼1 / 新」
- **玩法**：每日挑战、Higher / Lower、盲猜轮廓、经济护照，进度只存在浏览器里（没有账号、没有后端）

### 拼图玩法

点「玩一局」开一局：目标是把某个省/州的体量用**最多 3 个国家**拼出来，合计不许超过目标、越接近越好；提交后给出本局 0–100 分与最优解，还可以「挑战好友」。**看答案**不计成绩，选满 3 个会自动提交。宽屏在地图上点国家；手机上地图只有 180px 高、小国点不中，改用一份可点的国家清单。一旦超了目标就当场说（「超了 X —— 取消一个再试」）。

### 别的几个入口

- **换个组合**：结果卡上可切「原版 / 熟脸 A/B / 随机」，熟脸版只从编辑精选的常见国家里凑 3–6 个，误差直接标出来，URL 带 `v`，分享链接打开还是同一版
- **年份回溯**：**目标和对照的世界都按同一年比**——把滑块往前拨，参照物的大小也跟着变（「今天这个地方放在当年是什么水平」）
- **随机一题 / 今日一地**：前者随机抽一个地方 + 指标 + 口径；后者按日期确定性地抽——今天所有人打开看到的都一样，方便互相发
- **搜索**：中文 / 拼音 / 拼音首字母都能搜（`广东` / `guangdong` / `gd` / `Texas`）
- **地图上的国家可以点**：点一下切到「世界 → 地方」，看它相当于哪些省/州
- **分享**：复制链接（选择状态、指标、口径、年份都写进 URL）、竖版分享卡、高清横版图、1960→2025 的动图回溯

### 界面上的一些讲究

- **界面顺序按新用户动线排**：先给结论，再是「选地方」，然后才是换换口味、指标、年份、口径
- **图注是「人话」**：结论那行是数字（「≈ 52 个国家之和」），图注是这句话的意思（「这 52 个国家加起来，也就抵得上一个河南省」）
- **对比是动态的**：换指标、换口径、换年份时，结论里的数字从旧值滚到新值，地图上的高亮从旧颜色淡到新颜色
- **动效归用户选**：系统开了「减少动态效果」就静默，但页脚的开关能自己开；系统确实关了动画时，页面会弹一句说明，点一下就打开

## 怎么用

三步：打开[在线站点](https://rockbenben.github.io/gdp-map/) → 在左边选一个省/州（可直接搜中文、拼音或首字母） → 右边地图立刻高亮出一组等价的国家，左上角给出「≈ N 个国家之和」。

几个常用操作：

- **想看它跟大国比**：在「对照方式」里选「比大国家」，结果写成「河南省 ≈ 巴西的 41%」这种说法
- **想反过来看**：点地图上的任一国家，切到「世界 → 地方」，看它相当于哪些省/州
- **想看当年什么水平**：拖「年份」滑块——目标与参照物会一起回到那一年
- **想发给别人**：右上角「分享」里复制链接（状态全在 URL 里），或下载竖版分享卡 / 高清横版图 / 动图

## 数据从哪来

| 侧 | 来源 | 口径 |
| --- | --- | --- |
| 国家 | IMF《世界经济展望》2025 年 4 月版（经 DBnomics 镜像） | 名义 GDP + 人口，1990–2025 逐年；现价美元 / 百万人，2025 为该版预测值 |
| 国家（1960–1989） | 世界银行 NY.GDP.MKTP.CD + SP.POP.TOTL | 名义 GDP + 人口，现价美元；与 WEO 衔接（美国 1989 → 1990 连续） |
| 国家面积 | mledoze/countries 的面积表（原样取用，含内陆水域） | 平方公里 |
| 中国省级 | 国家统计局《中国统计年鉴》表 3-9《地区生产总值》+ 表 2-5/2-6《分地区年末人口数》 | 名义 GDP（亿元），**2000–2024 逐年**；2000–2011 取年鉴网页版的 HTML 表（程序解析），2010–2024 取年鉴表格图片的读数（落库在 `data/provincial-gdp-history.json`）；按当年年均汇率折美元；人均 = GDP ÷ 人口 |
| 港澳台 | IMF WEO（1990 起）+ World Bank NY.GDP.MKTP.CD / SP.POP.TOTL（1960–1989） | 香港 1960–2025、澳门 1982–1989 + 2001–2025（1990–2000 无统计）、台湾 1990–2025；走省级池，不进国家池 |
| 中国省面积 | DataV.GeoAtlas 边界几何（球面面积换算） | 平方公里，估算值 |
| 平价换算 | IMF WEO 的 PPPGDP ÷ NGDPD | 中国 2.035、美国 1.000（美国是 PPP 基准，恒为 1）、香港 1.390 |
| 美国各州 | BEA 州级名义 GDP 与人口（SAGDP2 现价美元 + SAINC4 人口，1997–2025） | 美元；人均由「总量 ÷ 人口」算；面积按 us-atlas 州界几何算 |
| 欧洲 NUTS-1 | Eurostat `nama_10r_3gdp` / `nama_10r_3popgdp`（2000–2024，逐年） | 94 个一级区（德国 16、法国 14、土耳其 12…），边界 Eurostat GISCO；「整个国家算一个 NUTS-1」的（如捷克、丹麦）不重复收录 |
| 日本都道府县 | 内阁府《府县民经济计算》与总人口（2023 年度） | 47 个都道府县，边界 Natural Earth；内阁府汇总里有 5 个县（石川、奈良、德岛、香川、宫崎）显示「-」，那 5 个从各府县自己公布的结果里读 |
| 汇率 | World Bank `PA.NUS.FCRF` | 年均官方汇率 |
| 价格基准（兜底） | World Bank `NY.GDP.DEFL.ZS`（美国 GDP 平减指数） | 两边通常取同一年，系数为 1；数据源给出不同年份时用它折算（只有比率有意义：1960→2024 差 8.16 倍） |
| 世界边界 | Natural Earth（经 D3 graph gallery 转换，ISO3 编号） | 台湾并入中国轮廓 |
| 中国边界 | 阿里云 DataV.GeoAtlas | 34 个省级行政区 + 南海诸岛（符合国内地图合规要求） |
| 美国州界 | us-atlas（TopoJSON，FIPS 编号） | 州界几何 |

交叉校验：31 个省合计与**统计公报口径**的全国 GDP 差 0.72%（地区加总 ≠ 全国的正常口径差）；美国 51 个州合计与全美 GDP 差 **0.13%**。

省级数据的数值是从年鉴官方表格（图片）人工读取后落库的（`data/provincial-gdp-2024.json` 是 2024 年，`data/provincial-gdp-history.json` 是 2010–2024 年的逐年读数），原图保留在 `data/raw/`，来源链接写在页面页脚，点击「官方原表」可核对。2000–2011 年的部分是年鉴**网页版**的 HTML 表，程序直接解析，不经人手。

## 限制

- **PPP 口径只有国家侧是官方数**：国家用 IMF 的 PPPGDP；省/州没有同口径的 PPP 源，用所属国家的 PPP 换算因子估算（页面上写明了）
- **熟脸组合是编辑精选，不是客观的「最出名」排名**：它只从几十个常见国家里凑 3–6 个，误差会直接标在结果卡上，可能比原版大；随机组合用固定种子，分享链接里的 `v` 决定是哪一版
- **省/州侧的数据年份不一样**：中国省级 2000–2024、美国各州 1997–2025、欧洲 NUTS-1 2000–2024，日本都道府县只有 2023 年，年份控件只放**目标有数据**的年份，两边都取那一年比（所以不用再跨年折价）（欧盟 94 个区里有 7 个有缺口：比利时三区 2003 年起、罗马尼亚四区只有 2000–2001 与 2012 年起）
- **日本都道府县是财年数据，国家池里的日本是自然年**：内阁府《县民经济计算》给的是「2023 年度」（2023-04～2024-03），47 县合计 621.7 兆円；而国家池里日本的 2023 值来自 IMF WEO 的自然年，约 591.9 兆円——**两边差约 5%**。所以拿日本府县跟「世界」比时，府县那一侧相当于略偏大（多含了 2024 年初那段涨价）。这是口径差异，不是读数错误。
- **1960 年以前不发布**：只有麦迪逊项目的估算，而省/州在那些年份没有统计，拿今天的省去比当年的猜测，结论是拼出来的
- 省/州现在覆盖中国、美国、欧洲 94 个 NUTS-1 一级区与日本 47 个都道府县；欧洲 NUTS 之下的一级（NUTS-2）、日本的市町村暂未接入（管线加一份源文件即可扩）
- 省级面积是按边界几何估算的（与官方公布值相差 1% 上下）；省级**人均**由「GDP ÷ 人口」算（年鉴公布的人均用的是年均人口，与我们发布的年末人口在旧年份能差 9%，三个指标必须自洽）
- 中国省级的历史值是**各版年鉴当时公布的数**：经济普查修订（三经普、五经普）会改动历史年份，所以相邻年份之间存在口径断点（如北京 2023→2024 涨 12%，2000→2001 涨约 50%），本项目不做跨版推算
- **玩法进度只存在本地**：每日成绩/连胜、Higher / Lower 与盲猜最佳、经济护照都在浏览器 localStorage；清缓存或换浏览器会丢，没有账号、没有后端、也没有全球排行榜。挑战好友是一个带目标与分数的静态链接（分数只作展示，按 0–100 夹取）
- 面积剪影对照用等积投影，保证画出来的大小就是真实大小之比

## 给开发者

```bash
npm install
npm run dev       # http://localhost:5173
```

数据产物已经提交在 `public/`，首次运行不需要抓数据。要更新数据再跑 `npm run data`（同时抓国家、中美两省、欧洲 NUTS-1 与日本都道府县四套源，其中欧洲与日本那两套是 `scripts/fetch-regions.mjs` 单独负责的）。

其它命令：

```bash
npm run build     # 类型检查 + 打包到 dist/
npm run test      # 核心算法、价格基准与玩法单元测试
npm run preview   # 预览打包结果
npm run acceptance # 浏览器级验收（自带服务器，不用先起 dev server）
npm run audit:ui   # 多分辨率 UI 审计：9 个分辨率 × 16 个场景，量溢出/裁切/触摸目标，还导出全站文字
npm run audit:docs # 把文档里对外的每个数（对象池、交叉校验、产物体积…）现算一遍核对
npm run screenshots # 重新生成 README 里的预览图
node scripts/websearch.mjs "查询词"   # 网页搜索（DeepSeek Search & Fetch API，要 DEEPSEEK_API_KEY）
```

想对着 dev server 跑验收：`node scripts/acceptance.mjs http://localhost:5173`。CI（`.github/workflows/ci.yml`）跑的就是 typecheck → 单测 → 构建 → 浏览器验收。

**算法**只有一小块是自己写的，其余都是成熟库（`src/lib/match.ts`）：`accumulate` 是一个带两种顺序和两种规则的通用累加器，四种对照方式都由它组合出来；`matchByStrategy` 把四种口径包成统一入口；`closestSingle` 给单个最接近的对象。累加是贪心的，所以结果是「一组对象」而不是一个——件数（51 个 / 3 个）正是这个工具想给的那个数字。指标定义集中在 `src/lib/metrics.ts`，换指标不用动算法。

**技术选型**刻意保持轻量：Vite + React 19 + TypeScript，没有 SSR、没有状态库、没有 UI 框架；地图与地球都是**纯 SVG**（没有 WebGL，低端设备与截图导出都能跑），数据管线是 Node 脚本，产物落在 `public/data` 与 `public/geo`。地球不用 three.js 是算过账的：分享卡、高清图、GIF 三种导出都是「克隆当前 SVG → 画进 canvas → 栅格化」，屏幕上的图和导出的图**一定是同一张**；WebGL 画出来的东西没法序列化成 SVG，要接上导出就只能维护两套渲染器。发布的 JSON 按真实精度收口：钱到元、人到人、人均到分、坐标到 5 位小数。

**部署**是纯静态站，没有后端、没有 API 调用，构建产物就是几个 JSON + 一个 JS 包。托管在 **EdgeOne Pages**：推送到 `main` 时，`.github/workflows/deploy.yml` 把构建产物推到 **`gh-pages` 分支**，EdgeOne 从那个分支取——同系列的其他项目都是这个模式。缓存与安全响应头写在 `public/edgeone.json`（`/assets/*` 是内容哈希所以长期缓存，`data/` 与 `geo/` 的 JSON 是固定文件名、内容会变所以不缓存）。自定义域名 `gdp.newzone.top` 的 DNS 记录还没加（要指向 EdgeOne 的 `*.pages.dnsoe4/5.com`，不是 `rockbenben.github.io`），在那之前本文的「在线试用」先指向 <https://rockbenben.github.io/gdp-map/>；域名上线后把 `index.html` 里的 canonical / OG 地址和本文的链接一起换过去即可。`dist/` 也可以直接丢到任何静态托管（`vite.config.ts` 里 `base: './'` 用的是相对路径，放子目录也能跑）。数据是构建期抓取好的静态 JSON，运行时不再访问外部接口。首屏只下载 `public/data/regions.json`（每对象的默认年，约 35 KB gzip），其余年份在 `public/data/regions-history.json`（1,038 KB，gzip 332 KB）里，页面加载后才合并——**两个文件都要部署**。

> 锁文件里的依赖指向官方源 `registry.npmjs.org`（不是国内镜像）——CI 跑在 GitHub runner 上，把一个第三方镜像放在构建关键路径上既慢又多一份可用性风险。本地想用镜像加速，临时改 npm registry 就行，**别把镜像写进锁文件**。要跟 CI 完全一致（按锁文件装），用 `npm ci`。
